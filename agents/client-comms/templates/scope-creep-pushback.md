# Scope Creep Pushback

Use when a client asks for work outside the agreed scope.

---

## Version 1: Small Addition (Easy Redirect)

Hi [CLIENT_NAME],

Great idea! [BRIEF_POSITIVE_COMMENT_ABOUT_THEIR_REQUEST].

That falls outside our current scope, but I have two options:

1. **Swap it in:** I can replace [LOWER_PRIORITY_ITEM] with this new request — same timeline, same budget.
2. **Add it on:** I can add this as an extra deliverable for [ADDITIONAL_COST] and [ADDITIONAL_TIME].

Which works better for you?

[YOUR_NAME]

---

## Version 2: Significant Addition (Firm Redirect)

Hi [CLIENT_NAME],

I appreciate you thinking bigger on this — [NEW_REQUEST] would definitely add value to the project.

To set expectations, this is a separate piece of work from what we originally scoped. Here's why:

- **Original scope:** [BRIEF_DESCRIPTION_OF_AGREED_WORK]
- **New request:** [BRIEF_DESCRIPTION_OF_NEW_WORK]
- **Impact:** Adding this would require approximately [HOURS/DAYS] of additional work

I'd recommend we finish the current scope first, then tackle [NEW_REQUEST] as a Phase 2. I can put together a quick proposal for it — would that be helpful?

This way, the current project stays on track and you get a clear picture of the additional investment.

[YOUR_NAME]

---

## Version 3: Repeated Scope Creep (Pattern Breaker)

Hi [CLIENT_NAME],

I want to make sure we're aligned on the project boundaries so we both get the best outcome.

Over the past [TIME_PERIOD], we've added several items beyond our original agreement:
- [ADDITION_1]
- [ADDITION_2]
- [ADDITION_3]

I've been happy to accommodate where I can, but these additions have added roughly [HOURS] hours of extra work to the project. Going forward, I'd like to handle changes through a simple change order process:

1. You describe the new request
2. I estimate the time and cost
3. We agree before I start the work

This keeps the project organized and ensures there are no surprises for either of us. Sound fair?

[YOUR_NAME]

---

## Key Principles
- **Always acknowledge the value** of their idea before redirecting
- **Never say "no"** — say "yes, and here's what that looks like"
- **Quantify the impact** — hours, cost, timeline shift
- **Offer options** — people feel better choosing than being told
- **Document everything** — follow up verbal scope discussions in writing
